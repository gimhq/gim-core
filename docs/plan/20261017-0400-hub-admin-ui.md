## 1. Decisions

| # | Decision | Source |
|---|---|---|
| A1 | The admin UI is a React + Vite SPA built to the `pma-web` baseline, in `hub/admin-ui/` (single app, no monorepo) | user 2026-10-17 |
| A2 | The built SPA is embedded in the `gim-hub` binary; a release stays one asset per platform, updated by lode | L1 |
| A3 | Admin UI and admin API are served only on a separate listener `GIM_HUB_ADMIN_LISTEN` (default unset = disabled; recommended `127.0.0.1:8081`), never on the client API listener | L1 |
| A4 | Login by admin token (`GIM_HUB_ADMIN_TOKEN_FILE`, only its hash kept in memory) giving an HttpOnly, SameSite=Strict session cookie (8 h), CSRF token on every mutation. Optional: trust an identity header set by a reverse proxy (traefik oidc) when `GIM_HUB_ADMIN_TRUSTED_HEADER` is set, token login can then be disabled | L1 |
| A5 | Metadata only. Messages are end-to-end encrypted; the UI never shows who talks to whom: group data is aggregate counts only | L1 |

## 2. Scope (v1)

- Overview: version and uptime, database and blob storage size, counts of users, devices, groups,
  blobs, push queue counters (queued, sent, failed, coalesced, upgraded), event retention.
- Users: search by user_id or handle; devices, sessions, last seen, hosting hubs. Actions: revoke a
  device session, suspend and unsuspend a user (suspended users cannot authenticate), release a
  handle.
- Federation: own PeerID and addresses, peer status (connected, outbox backlog, last error);
  allowlist view and edit, applied immediately (same effect as SIGHUP).
- lode (shown only when `LODE_DIR` is set, read from `state.json`): current, available, last good,
  history. Actions: check now, update to the available version, restart, roll back.
- Configuration: effective configuration, read-only, secrets redacted.
- Audit log: every admin action (time, actor, action, target, source IP), persisted and listed.

Out of scope: multiple admins and roles, content moderation, editing configuration files,
message/blob retention policies (separate item).

## 3. Delivery

- Admin API under `/admin/api/*` on the admin listener, documented in `docs/admin.md` and an
  `admin-openapi.json` (utoipa), separate from the client `openapi.json`.
- `scripts/check.sh` also runs the admin UI gates (bun: lint, typecheck, test, build).
  `release.yml` and both Dockerfiles build the SPA before `cargo build`; a missing build fails the
  build instead of shipping an empty UI.
- Deploy: `deploy/lode/lode.toml` and docs show the admin listener and a traefik route with the
  `oidc` middleware.

## 4. Acceptance

- Unit and integration tests of the admin API: login, session expiry, CSRF rejection, every action
  and its audit entry, suspended user cannot authenticate, allowlist edit takes effect.
- Security test: no `/admin` path answers on the client API listener; the admin listener refuses
  all API calls without a session.
- Frontend tests per `pma-web` and one browser E2E: login, search a user, revoke a session, edit the
  allowlist, trigger a lode check (lode panel against a fake `state.json`).
- `scripts/check.sh`, fed-test (fed, mh) and lode-smoke stay green; the release asset still
  verifies and runs under lode.
